## Mandatory SAP-side Context action

Perform this sequence in the target SAP system:

1. Pull commit `c5bacb5` (or its descendant) to import the exact parameter
   records into `YMMGRNNOTE_INT`.
2. Open `YMMGRNNOTE_INT` in SFP and add `FORMATTING_ERROR`,
   `INTERNAL_ERROR`, `SEND_ERROR`, and `USER_CANCELED` with SFP's native
   exception editor.
3. Verify the interface parameter names/types against the table above.
4. In the generated Context, inspect every component of `LT_MSEG` and the
   imported `LS_MSEG`. For every component whose DDIC type is `QUAN`, set its
   SFP Reference Field to the exact unit component shown by that component's
   DDIC reference; for every `CURR`, set its Reference Field to the exact
   currency component shown by its DDIC reference. Verify that each selected
   unit/currency target is declared and visible in this interface/Context.
5. Activate `YMMGRNNOTE_INT`, then activate `YMMGRNNOTE_ADT`.
6. In `YMMGRNNOTE_ADT` Form Builder, manually drag/drop every required
   interface node from the left **Interface** tree into the right **Context**
   tree: the necessary import nodes, the required `LT_MSEG` table node, and
   their required children. Confirm the mapped nodes appear beneath the
   Context root. The trees are separate; do not expect a synchronization
   command to populate the form Context automatically.
7. Stage, commit, and push the resulting SAP-generated SFPF/SFPI
   serialization through abapGit before editing any bound XDP layout.

This is mandatory because the Context is a linked `CL_FP_NODE` object graph
generated by SFP as nodes are placed in Form Builder; hand construction
cannot safely establish the SAP-internal node IDs and links that XDP data
bindings require.

Until that pull completes, leave the XDP unbound. No driver, NACE, or
cutover change belongs to this phase.

## QUAN/CURR evidence and constraint

| Legacy expression / field | Role evidenced by XML | DDIC QUAN/CURR classification | Exact reference target |
|---|---|---|---|
| `WA_MSEG-ERFMG` | Accepted Quantity print field and calculation factor | Unresolved: `ZEXTRA_FIELD` component metadata was not supplied | Inspect DDIC reference in SFP; do not infer from `ERFME`. |
| `WA_MSEG-ERFME` | Unit print field | Unresolved as a reference target until `ZEXTRA_FIELD` is inspected | Verify whether it is the DDIC unit reference for `ERFMG`. |
| `WA_MSEG-DMBTR` | Unit-rate calculation operand | Unresolved: custom structure component metadata absent | Inspect DDIC currency reference in SFP. |
| `WA_MSEG-PEINH` | Unit-rate divisor | Classification/reference not supplied | Verify in SFP before calculation implementation. |
| `WA_MSEG-VAT`, `WA_MSEG-BNBTR` | VAT/freight aggregation operands | Unresolved: custom structure component metadata absent | Inspect DDIC currency references in SFP. |
| `LV_UNIT1`, `FINAL_AMT1`, `TOT_AMNT`, `VAT`, `SUM` | Legacy global calculated/aggregate display values | XML gives ABAP types (`ZERFMG`, `DMBTR`, `KWERT`, `BNBTR`) but no generated Adobe global/reference representation | Do not declare/serialize globals or references until SFP design decisions and exact target metadata are captured. |
| `IV_WAERS` | Inbound `WAERS` import | Currency-key type evidenced | Available as an interface candidate only; whether it is the correct reference for each CURR field is unproven. |
| `IV_KURSF` | Inbound `BAPICURR_D` import | Exchange-rate type evidenced, not a currency key | Never use as a CURR reference field. |

The present generated SFPI intentionally retains `<REFERENCE_FIELDS/>` and
no extra globals. The XML/program extraction establishes neither the
component-level DDIC references of `ZEXTRA_FIELD` nor a proven generated
reference-field record for this form. Creating `SFPREF` entries or globals
would therefore be fabricated metadata.
