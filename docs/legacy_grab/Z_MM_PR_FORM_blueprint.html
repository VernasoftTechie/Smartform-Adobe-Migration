04

Findings

Real housekeeping the extraction surfaced — carried into the Adobe design as decisions, not silently dropped.

Leave out
Live debugger statement
break abap1. sits active inside the %CODE15 node in the TYPE window. Not carried into the Adobe design — flagged for the driver/form owner to remove from the source Smart Form too.
Confirm
SO10 header text read
The MAIN window reads a standard text via READ_TEXT — object EBANH, ID B01 ("Header Note"). Needs a matching text object per requisition; not previously in the legacy-grab checklist — added.
Leave out
Dead code, three nodes
CURRENCY, %CODE20, and part of %CODE15 are fully commented out. Confirmed inactive — excluded from the design, not migrated.
Form-owned dependency
Two embedded Z function modules
ZABF_DATE_TO_DAY, ZABF_ISP_GET_MONTH_NAME — called from inside the form's own DATE window, not the driver. A dependency class the driver-only source scan can't see; now tracked separately per §02.

Where this generalizes to 500+

Nothing above is bespoke to this one form — it's the first run of a pipeline built to repeat.

1
Legacy grab
Interface, driver context, output determination — automated, one report run per form.
2
Global sweep, once
Every SmartStyle and every SE78 graphic in the system, in one pass — already done for this landscape.
3
Utilities → Download
The one manual step per form: export the real design XML. Everything in §01–04 above came from this.
4
Cross-reference, automatic
Style and logo references in the export get matched against the global inventory — usually a hit, not a rebuild.
5
Design spec, like this one
Window map, field bindings, findings, risk score — read, not guessed.
6
Build, validate, sign off
SFP migration wizard against the spec, OTF-vs-PDF diff on real data, named sign-off for anything Medium or above.
46
distinct SmartStyles already catalogued system-wide — most future forms will match one, not need a new one

What doesn't change, at any scale

Driver programs stay untouched
Read for context only. Two drivers can call the same form for different reasons — editing one risks the other.
Interface extended, never broken
2 new fields, both optional with a safe blank default — where the form's own embedded ABAP fetched something FormCalc/JS can't (build checklist §6). Every existing field, and every unmodified caller, is unaffected.
Nothing automated without verification
Every table and API used above was proven against this system first — a wrong guess fails safely, never silently.
Unresolved items are logged, never dropped
Driver, output determination, and the SO10 text object above are open — tracked, not hidden.
