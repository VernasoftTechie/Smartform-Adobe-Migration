# ZMMCG_PO_SF - conversion map (strategy S12, section 4)

Written 2026-10-12 by applying the S12 decision catalogue (`docs/strategy/S12_legacy_construct_to_adobe_pattern_catalogue.md` on `main`) to the raw legacy export (`vernasofttechie-zmmcg_po_sf/zmmcg_po_sf.xml`).
Every structural legacy node (pages, windows, alternatives, graphics, program lines, templates, tables, table lines, sections, folders: 145 in all; table columns and text nodes are covered by their row) has a row.
`node tools/zmmcg_po_sf/conv_map_check.mjs .` checks this file against the raw export and the generated files (all nodes named, pattern id and status per row, every `xdp:NAME` exists in the layout,
every live program-lines node is in the Initialization, no disabled node is mapped as built). Status words: **built** (in the layout / Initialization of this ticket, not yet rendered in the client's SAP), **dead**
(permanently disabled in the legacy form by `1 = 2` / `2 = 3`, deliberately not rebuilt, DEP-10), **proposal**, **open**. `xdp:NAME` = object name in `src/zmmcg_po_sf_adt.sfpf.xdp`; labels are `GS_LABELS-LB_*` (catalogue `zmmcg_po_sf_labels_catalogue.md`).

## Decisions S12 made explicit (and what changed because of them)

| Aspect | S12 rule applied | Decision | Change made on 2026-10-12 |
|---|---|---|---|
| Letterhead (page-1 windows) | rule 3: master page for content repeating on every page, body block when it depends on data or sits in the flow | the eight page-1 windows stay a positioned block (`HEADER_AREA`) at the start of the body flow; logo and watermark are page-area objects (P01 b) | none; preview comparison with a master-page variant stays an open extension point |
| Variant blocks (ZPOT grid, goods / service, comments) | principle 5: prepared data, bound empty table, choice, ready hide, in that order | `ready` hide (the Context-side TRUE / FALSE groups are unproven) | the seven hide scripts now carry `runAt="server"` as all 17 `ready@$form` hides of the client form ZEZC_SD_INVOICE_IN_EMAIL |
| Alternative node (watermark) | rule 1: prepared data beats layout logic | one prepared label, no script | watermark is `LB_HDR_WATERMARK`; the layout has no calculate script left; the model reads alternatives generically (TRUE: condition, FALSE: negation) and stops on a compound condition |
| Item / totals tables | rules 2 and 4: bound table; trailer only when the legacy prints at every page break | table + leader, footer rows after the table, no trailer | none |
| Pagination | principle 3, P07 pitfall: no silent `keep` | none (the legacy has no protect command) | none; question to the client below |
| Terms | P25 | one prepared table | none (DEP-14) |
| Page numbers | S12 section 2.3 | not added (the legacy prints none) | none |
| Hidden defects found by the mapping | principle 4 | Context node names were up to 36 characters; the extract dropped alternative conditions | name limit 30 (import error "SFPF deserialization error: Invalid request" of the previous commit), generator and `verify.mjs` enforce it; extractor prints `TRUE branch if ...` |

## Questions for the client (also in the status file)

1. Import log: if the import still fails after this version, the full abapGit log text (object, message, line) is needed; the Context node names are the only found cause and are not proven.
2. Should the totals and the terms stay together on one page (`keep`), or break exactly like the legacy form (the legacy has no protect command)? Only a printout with a table crossing a page break can show the legacy behaviour.
3. Should the letterhead be built as master-page objects instead of a block in the flow? Both render; the choice changes only the Design View and the effort to maintain it.
4. Is the inline character format `C4` in "Last Changed On:" bold or normal? (the style `ZMM_PURCHASE_REQ` / `ZWSA_COMMON_STYLE` definition is not in the export).
5. The earlier questions stay open: label utility class, runtime logo, page numbers wanted, one wording for all languages.
